# NextMusic · Phone 同源风格 · HD / Car HTML

交付两份可离线打开的独立 HTML：

- `NextMusic-HD.html`：HD 侧栏导航、底部常驻播放条、较丰富的内容浏览与键盘焦点操作。
- `NextMusic-CAR.html`：Car 顶部导航、左侧常驻播放器、大触控区和更精简的首屏。

直接双击文件即可打开。图片、样式和脚本已内嵌，无需安装依赖。手机版和 APK、本机 / NAS 原生应用源码未被修改。

## 本次确认的方向

以用户认可的手机版为视觉与内容基准。用户明确选择「手机版同款黑灰＋原版绿色」，覆盖此前的冰蓝配色方向。

- 共用 `#121212` 页面底、`#1A1A1A` 卡片、`#232323` 次级面、`#FFFFFF` / `#B3B3B3` 文字层、`#1ED760` 强调色、`#FF5A76` 收藏心。
- 保留纯色黑灰页面，绿色只承担主播放、当前歌曲和选中状态的提示。
- 复用原项目 Logo、首页照片、媒体库品牌图标和黑胶盘；替换此前 Demo 的波形标志与另选的风景资源。
- 两端共用「全部 / 音乐 / 播客」、每日精选、我的收藏、私人雷达、夜深人静、华语经典、最近播放等内容名称。
- 媒体库依照手机版分为我的曲库、公共曲库、第三方媒体库；云曲库等支持歌曲 / 专辑 / 歌手浏览。
- 我的音乐分为歌单 / 歌手 / 专辑，提供收藏与详情入口。
- 搜索分为歌曲 / 歌手 / 专辑，保留最近搜索和热门词。
- 未收藏的当前歌曲打开收藏到歌单面板；已加入「我喜欢的」可直接移除，已收藏心形为粉色。
- 播放页共用原版黑胶，提供进度、播放模式、音质、速度、定时、设备与音效入口。歌词无数据时明确展示空态。
- 不以桌面页面整体缩放实现 Car。Car 在 1280×720、1920×1080、1024×600 的主要首页内容可以完整显示，800×480 内容区滚动且主控常驻。

## 三套主题与视觉层次

新增完整浅色主题，包含顶部与侧栏、底部播放条 / 常驻播放器、歌单、搜索、曲库、音源、音效、播放页、队列与弹窗。默认保留深色；在右上角太阳 / 月亮按钮一键切换，或在「设置 → 外观」选择浅色、深色、纯黑。播放页也有明暗切换。选择自动保存，页面加载前读取，刷新无需重新选择。

浅色采用原手机版的 `#F6F7F9` 画布、白色卡片与深色正文；强调色仍为 Next Green，文字用更深的绿色。深色增加了封面对应的局部色调、卡片描边、快捷入口副标题、分区标记与推荐标签，避免大面积单色卡。照片卡与榜单保留深色承载面和白字。

两端各通过 15 项主题检查，含三套主题切换、刷新恢复、播放页切换、浅色下 35 个页面构建，以及各 4 种尺寸下主控和主题入口的可见性。主题截图命名为 `qa/HD-浅色-*.png` / `qa/CAR-浅色-*.png`，记录见 `qa/themes.json`。

## 单层返回修正

HD 内页只保留外层顶部返回，内页标题不再重复生成返回按钮；首页等无返回需求的页面隐藏顶部返回。Car 只保留内页返回。正常页面按实际访问历史退回，避免返回时再次把当前页压入历史；歌单导入按「预览 → 链接 → 平台」逐步回退，Esc 同步遵循此规则。

两端各 35 个页面检查到的可见返回按钮均不超过一个，并验证了歌单返回、曲库 → 歌手 → 专辑的逐级返回和导入分步返回。记录见 `qa/back-navigation.json`。

Chrome 中通过 74 项浏览器检查（HD 38、Car 36），两端各 35 个页面可构建，没有捕获运行错误或外部网络请求。

覆盖首页分类、歌单播放、收藏面板、队列与模式、黑胶播放页、歌词空态、音质同步、三类搜索、搜索转义、曲库分组与库内歌手浏览、歌手收藏、歌单导入、刷新恢复、清空确认和空队列保护。HD 另检查方向键焦点移动和回车激活。

尺寸检查：HD 为 1280×800、1920×1080、1024×768、800×600；Car 为 1280×720、1920×1080、1024×600、800×480。检查内容区无横向溢出、主控可见。HD 首页保留向下浏览的长页面。

两份 HTML 均通过 `file://` 离线打开检查；实际页面截图在 `qa/`。以上是桌面浏览器模拟，尚未验证真实 HD / 车机硬件或遥控器。

## 演示范围

这是设计与交互原型，不是把完整原生播放器迁移到 HTML。歌曲、歌单数量与媒体库为可操作的示例数据；播放为计时模拟，没有真实音频。服务器连接、账号、音源脚本、下载、音效、设备搜索等为界面流程演示，不会访问实际账号、目录或播放设备。

在同一浏览器下保存队列、歌曲收藏、导入歌单、歌手 / 专辑收藏和外观偏好。各浏览器对 `file://` 存储的隔离方式不同，不应将两个离线文件间的状态恢复视为真实跨端同步。
